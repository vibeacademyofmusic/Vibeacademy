IMPORT BEHAVIOR
- Only official Violin and Piano foundation catalogs are targeted. TEST_* trees are never converted or changed; missing official trees are created separately.
- Existing program/level/subject identities are reused, recognizing G1/GRADE_1, Pre/Pre Grade and Sight Reading/Sightreading aliases. Ambiguities abort the entire import.
- Adds only enough slots to bring an existing subject to 10 total items across all its components. Existing 10+ items are preserved, including inactive items. More-than-10 subjects are explicitly reported; they are not silently reduced.
- Existing lesson titles, component mapping, completion policies and statuses remain unchanged.
- New rows are INACTIVE; new subjects/components/items are optional. New levels/subjects use MANUAL; the technical LESSON_DRAFTS container uses the schema's DIRECT_ASSESSMENT default and stays inactive. This is storage for authoring, not an approved assessment mapping.
- Positive sequence slots for missing levels are inserted before the next recognized level, preserving existing IDs and relative order. Existing sequence numbers may shift; old/new values appear in the report. Conflicting pre-existing order is not rewritten.
- No enrollments or progress rows are created/updated. Five academic enrollment/progress tables are locked and checksummed before/after; any difference aborts the transaction.
- No permanent schema migration, RPC, RLS, permission grant, outbound message or production write is introduced.
- CLI verifies .env.local against local Supabase status and the Docker database port. Default is dry-run with rollback. --apply first repeats the dry run and creates a restricted custom-format backup of the five curriculum catalog tables. This is NOT a full system recovery backup.
- CLI does not start, reset, restore, reconfigure or migrate Supabase. Import must use the existing local database serving port 3000 after the local operator verifies that runtime.
